# Human Resource Management System(HRMS) Dalnex

A web application for managing employee records, attendance, leave, payroll, and everyday HR
operations. It includes an administration portal for HR teams and an employee self-service area,
with access controlled by user roles and permissions.

## Features

- **Employee management:** Maintain employee profiles, onboarding, documents, and exit records.
- **Attendance:** Track daily attendance, punch records, holidays, and attendance registers.
- **Leave and approvals:** Manage leave, duty, and compensatory-off requests with approval workflows.
- **Payroll:** Process payroll, calculate salary components and deductions, and generate payslips.
- **Employee self-service:** View personal attendance and pay information, submit requests, and review
  assigned approvals.
- **HR operations:** Manage reimbursements, assets, company policies, notices, and helpdesk tickets.
- **Administration:** Configure users, permissions, application settings, and review audit activity.

## ZKTeco device attendance

The device integration is maintained in [`zkteco/`](zkteco/). Run `npm run dev`
and `npm run device:bridge` in separate terminals, or use `npm run dev:device` to start
both together.

## Source layout

Filenames describe their responsibility. TypeScript and JavaScript utilities use kebab-case,
React components use PascalCase, and custom hook files use `useCamelCase`. Python modules use
snake_case. Framework entry points such as `page.tsx` and `layout.tsx`, and standard Python names
such as `__init__.py` and `requirements.txt`, are retained. `__pycache__` is generated by Python
and is not source code.

Shared values live in files named for their purpose: `attendance-status.ts`, `branch-colors.ts`,
`document-categories.ts`, `indian-states.ts`, `portal-navigation.ts`, and `notice-retention.ts`.
Library filenames also state their responsibility, such as `portal-access.ts`, `server-auth.ts`,
`display-formatting.ts`, and `compensatory-off-settlement.ts`.

The HRMS remains one Next.js application. Pages load data from `src/lib/queries/<feature>.ts`;
these modules are marked `server-only` and retain scoped database access. Import query results
into client components with `import type`. Import the needed feature directly instead of adding
a shared query barrel.

Server Actions authorize callers and coordinate requests, notifications, and page revalidation.
The leave-attendance workflow in `src/lib/requests/leave-attendance.ts` receives the authorized
client from its action. Payroll arithmetic lives in `src/lib/payroll/payslip-calculation.ts` and
uses integer paise without database dependencies; `src/lib/db/payroll-processing.ts` retains
transaction handling, run locks, data loading, and Decimal128 persistence. Document summaries
are pure functions in `src/lib/documents/document-summary.ts`.

Run `npm test` for payroll, authorization, leave-attendance, and module-boundary regressions.
Use `npm run check` for formatting, filenames, lint, and types, and `npm run build` for the
production build.

| Folder                  | Responsibility and entry points                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| `src/lib/queries/`      | Feature queries for attendance, employees, documents, payroll, and other HR screens.                            |

## CSS naming

Use descriptive kebab-case names for styles and update their component references together.
For example, use `app-layout`, `card-header`, `notification-message`, `table-column-menu`,
and `attendance-status-present`. Theme variables follow the same convention, such as
`--text-primary`, `--font-monospace`, and `--attendance-present-background`.

Keep shared styles in `src/app/globals.css`, page styles beside their routes, and reusable
feature styles beside their components. Responsive and print rules use the same class names.

Use descriptive names in the matching React code too: `useNotifications` returns
`showNotification` and `notificationContainer`; shared components include `TableColumnMenu`
and `AttendanceStatusBadge`. State values and setters should describe what they hold, such as
`searchQuery` / `setSearchQuery` and `maintenanceRecords` / `setMaintenanceRecords`.
Keep React API names such as `useState` unchanged, and preserve external request field names
when renaming local variables.
